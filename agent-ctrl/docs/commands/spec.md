# `/ac:spec` composition

- **Target and responsibility:** Explicit checkpoint for writing or refining one behavior spec that the user approves before `/ac:plan` designs the implementation.
- **Sources:** `agent-ctrl/.local/spec-kit/templates/commands/specify.md`, short-name and numbering rules, informed defaults, marker cap, and self-validation loop; `agent-ctrl/.local/spec-kit/templates/commands/clarify.md`, coverage taxonomy, one-question-at-a-time refinement with recommended answers, and the clarifications log; `agent-ctrl/.local/spec-kit/templates/spec-template.md`, prioritized user stories, `FR-###`/`SC-###` identifiers, edge cases, and assumptions; `agent-ctrl/.local/ai-native-engineering-workspace/prompts/spec.md` and `specs/TEMPLATE-mini.md`, hostile-reader self-critique, preserved-behavior criteria, and the draft/approved/in-progress/shipped lifecycle; OpenSpec public documentation, living spec plus ADDED/MODIFIED/REMOVED deltas merged on archive; Kiro public documentation, EARS requirement patterns.
- **Behavior taken:** Repository-first discovery, one change spec per run under `specs/changes/<NNNN>-<slug>/`, EARS requirements with Given/When/Then scenarios, delta and preserved-behavior blocks for changes to existing capabilities, at most three clarification markers, checklist and hostile-reader passes, in-place refinement on re-run, and explicit user approval before planning.
- **Merge:** spec-kit's `specify` and `clarify` collapse into one command whose second mode is triggered by passing an existing spec path. `analyze`, `checklist`, `tasks`, `implement`, and `converge` are not separate commands: their responsibilities live in `/ac:plan`, `/ac:plan-validate`, `/ac:run`, and `/ac:verify` through the traceability and deviation rules in `work-planning/references/spec-contract.md`.
- **Provider adaptation:** Specs live in `specs/` at the project root rather than provider-private or tool-specific directories; no bash or PowerShell helper scripts, extension hooks, feature pointer files, or branch automation are used — the agent performs numbering and directory creation directly.
- **Exclusions:** Constitution as a separate artifact (the project's own instruction files serve that role), per-domain checklist files, task-list grammar, GitHub issue export, automatic commits, and provider runtime state were omitted.
