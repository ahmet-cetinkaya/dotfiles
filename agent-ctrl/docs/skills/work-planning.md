# `work-planning` composition

- **Target and responsibility:** Repository-first, decision-complete planning with observable acceptance criteria.
- **Sources:** `agent-ctrl.old/skills/intent-driven-development/SKILL.md`, “When to Activate,” context, acceptance, and handoff; `agent-ctrl.old/settings/claude/agents/omo-prometheus.md`, interview, exploration, and one-plan sections; current [oh-my-openagent](https://github.com/code-yeongyu/oh-my-openagent) `packages/shared-skills/skills/ulw-plan/SKILL.md`, explore-first and decision-complete planning; [spec-kit](https://github.com/github/spec-kit) `templates/spec-template.md` and `templates/commands/{specify,clarify,analyze}.md`, spec structure, identifiers, marker cap, coverage taxonomy, and requirements checklist; [ai-native-engineering-workspace](https://github.com/engindemirog/ai-native-engineering-workspace) `specs/TEMPLATE.md`, `specs/TEMPLATE-mini.md`, and `prompts/{spec,plan,verify}.md`, status lifecycle, preserved behavior, criterion ↔ test map, and hostile-reader critique, plus `workflows/refactor.md`, green baseline, characterization tests, and unchanged-test proof for behavior-preserving plans; OpenSpec and Kiro public documentation, living-spec deltas and EARS patterns.
- **Behavior taken:** Quick versus full depth, questions only for non-discoverable choices, explicit scope/decisions, per-task evidence, durable draft handoff, explicit approval before execution, and an opt-in Spec First mode with its own contract, quality passes, and plan traceability, plus local user-requested optional phased delivery for plans whose total PR would not be reviewable.
- **Merge:** Acceptance-brief discipline and OMO planning are combined into a short routing skill with separate plan and acceptance references; spec-driven references (`spec-contract.md`, `spec-quality.md`) sit beside them so `/ac:spec` and `/ac:plan` share one vocabulary. The plan contract owns the optional phase mapping, branch/PR topology, and final umbrella verification.
- **Provider adaptation:** Plans live in `.agents/plans`, specs in `specs/` at the project root; provider draft state, tool-call examples, helper scripts, and model routes are absent.
- **Exclusions:** Separate constitution, checklist, tasks, and implement stages, mandatory interviews, runtime ledgers, fixed task grammar, branch automation, and provider approval machinery were excluded.
